# 前端 AI 协作工作流

## 一、目标

本仓库用于统一管理团队共享的 AI 工程规范和可复用的开发技能。

当前主要技术栈：React + TypeScript。

当前使用方式：个人开发。

未来目标：让多个开发者在不同 AI 工具中遵循一致的工程规范。

## 二、规范文件说明

* `rules/00-core.md`：通用工程规范。
* `rules/10-react-typescript.md`：React 与 TypeScript 开发规范。
* `rules/20-debugging-and-review.md`：问题排查与代码审查规范。
* `skills/react-feature/SKILL.md`：React 功能开发流程。

以上文件是共享规范的主要来源。

业务项目可以增加自身的专属规则，但不应在没有说明的情况下引入与共享规范冲突的要求。

## 三、在 ChatGPT 网页版中使用

1. 明确当前业务项目及任务涉及的文件。
2. 向 ChatGPT 提供相关源码和必要的共享规则文件。
3. 要求 ChatGPT 在提出或修改代码前先理解现有实现。
4. 优先采用小范围修改，避免不必要的整体重写。
5. 在本地检查代码差异，并执行适用的项目验证命令。

建议在任务开始时使用以下提示词：

“请遵循我提供的 AI 工程规范。先检查现有实现，分析最小且合理的修改方案。不要在未经检查的情况下假设文件、依赖或接口字段存在。完成修改后，请说明涉及的文件、修改原因以及需要执行的验证步骤。”

对于较复杂的功能开发任务，可以额外提供 `skills/react-feature/SKILL.md`。

## 四、在 TRAE 中使用

1. 打开业务项目。
2. 查找当前 TRAE 版本支持的项目规则或项目指令配置入口。
3. 如果支持直接引用外部规则文件，优先采用引用方式。
4. 如果不支持，则将共享规则的内容复制到 TRAE 支持的项目规则位置。
5. 通过一个小型开发任务验证规则是否真正生效。

不要默认 TRAE 会自动同步 TeamAI 资源。应先确认当前版本的集成方式和规则加载行为。

## 五、规范维护

* 优先在本仓库中维护共享规则。
* 修改规则后，先在真实任务中验证，再将其作为稳定规范。
* 业务项目特有的要求应保留在业务项目自己的规则中。
* 向团队共享之前，检查是否包含敏感信息、凭据、内部地址或不应公开的项目路径。

## 六、验证要求

根据业务项目实际提供的脚本，执行类型检查、代码检查、测试和构建。

只有实际执行成功的检查，才能报告为通过。

规则文件用于提高 AI 开发的一致性，但不能替代 TypeScript、ESLint、自动化测试和构建等工程验证。
