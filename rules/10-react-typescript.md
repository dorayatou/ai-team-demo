# React + TypeScript 开发规范

## 一、React 组件

* 遵循项目已有的组件风格和架构约定。
* 在符合项目现有规范的前提下，优先使用函数组件和 Hooks。
* 让组件保持清晰的职责，避免单个组件承担过多无关逻辑。
* 当抽取公共逻辑确实有助于理解和复用时，可以使用自定义 Hook 或工具函数。
* 不要为了抽象而抽象，避免为一次性逻辑引入不必要的组件层级。

## 二、TypeScript 类型

* 优先复用项目已有的接口、类型、枚举和 API 响应定义。
* 为新增的公共函数、组件 Props 和重要数据结构定义明确的类型。
* 能够合理定义类型时，尽量避免使用 any。
* 不要通过类型断言掩盖实际存在的类型错误。
* 在业务逻辑中明确处理 null、undefined、可选字段和空值情况。

## 三、状态管理与组件渲染

* 引入新的状态管理方式前，先检查项目当前使用的方案。
* 避免重复存储可以直接推导得到的数据。
* 保持副作用逻辑清晰，并正确处理依赖和必要的清理操作。
* 只有在确认存在渲染或性能问题时，才针对性处理不稳定的对象、数组或回调引用。
* 不要在没有证据的情况下进行过度性能优化。

## 四、样式规范

* 遵循项目现有的样式方案，例如 SCSS、CSS Modules 或已有组件库。
* 优先复用项目中的设计变量、颜色、间距和组件样式。
* 如果项目统一使用样式文件，不要随意改为内联样式。
* 涉及页面布局时，适当检查响应式表现、内容溢出、长文本、加载状态和空状态。

## 五、数据与接口

* 遵循项目现有的 API 请求、错误处理和数据转换规范。
* 根据项目架构，将数据请求逻辑与展示逻辑合理分离。
* 在适用的场景下，正确处理加载中、成功、空数据和错误状态。
* 不要凭空编造接口字段，也不要在没有依据的情况下修改请求参数或响应结构。

## 六、依赖与兼容性

* 使用 React、TypeScript 或第三方库的功能前，先确认项目实际安装的版本。
* 优先选择兼容现有依赖的实现方式。
* 不要仅为解决一个局部问题就随意升级依赖。

## 七、提交修改前的检查

* 根据项目情况执行类型检查、代码检查、测试或构建。
* 检查最终差异，排除无关修改、意外删除和调试代码。
* 对重要边界条件进行必要验证。
* 说明尚未验证的行为及已知限制。
