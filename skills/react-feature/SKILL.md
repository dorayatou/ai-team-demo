# React 功能开发流程

当需要在现有 React + TypeScript 项目中新增功能或扩展已有功能时，按照本流程执行。

## 第一步：理解需求

* 明确用户希望实现的具体行为。
* 确认输入、输出、交互方式和重要边界条件。
* 如果需求歧义会影响架构或业务行为，先提出有针对性的澄清问题。

## 第二步：检查现有项目

修改代码前，优先阅读以下相关内容：

* 目标页面或组件。
* 相关子组件和自定义 Hook。
* 类型定义与 API 接口。
* 状态管理逻辑。
* 现有样式和测试。
* package.json 中的脚本及相关依赖版本。

如果任务涉及较多文件，应先简要说明当前实现方式，再进行修改。

## 第三步：制定适当的修改计划

明确：

* 哪些文件需要新增或修改。
* 每个文件分别负责什么。
* 功能涉及的数据如何流转。
* 需要执行哪些验证。

计划的复杂度应与任务相匹配。简单修改不需要冗长的规划过程。

## 第四步：实现功能

* 遵循项目现有的目录结构和命名规范。
* 优先复用已有组件、Hook、工具函数和依赖。
* 使用明确且符合现有业务结构的 TypeScript 类型。
* 根据实际场景处理加载、空数据、错误和成功状态。
* 遵循现有样式方案和响应式布局规范。
* 避免无关重构和超出需求范围的修改。

## 第五步：验证结果

* 根据项目情况运行类型检查、代码检查、测试或构建。
* 检查最终代码差异，排除无关修改。
* 检查重要边界条件和用户交互。
* 修复本次修改引入的问题。

## 第六步：汇报结果

完成后说明：

* 实现了什么功能。
* 修改了哪些文件。
* 采用了哪些重要设计方案。
* 实际执行的命令及其结果。
* 仍然存在的限制或待处理问题。
